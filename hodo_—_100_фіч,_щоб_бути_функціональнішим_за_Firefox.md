# hodo — 100 фіч, щоб бути функціональнішим за Firefox

Каталог для агента. Позначки: **\[P0\]** — без цього браузер не працює на реальних сайтах; **\[P1\]** — конкурентна функціональність; **\[P2\]** — диференціатори, можна пізніше. Посилання (M2, M4…) — на milestone з ТЗ.

**Чесний орієнтир:** за кількістю фіч Firefox перегнати реально, за веб-сумісністю (20+ років стандартів) — ні. Тому спершу закрити всі \[P0\], а виграти на трьох речах: приватність за замовчуванням, RAM і power-user інструменти, вбудовані замість розширень.

## Конфлікти з принципами hodo (вирішити до старту)

- **Хардкап 2 MiB** не сумісний із медіа (9) і завантаженнями (52): для них потрібен окремий стрімінговий режим зі своїми лімітами; кап лишається для HTML/CSS/JS/маніфестів.
- **`unsafe_code = forbid`:** sandbox (23), UIA/AT-SPI (83), MPRIS/SMTC (89), ключі ОС (81) та медіа-декодери зазвичай потребують FFI. Лишати лише через безпечні крейти — це те саме рішення A/B, що й у M3.
- **RAM:** site isolation (23), локальний AI (92), переклад (88) і GPU (M6) збільшують споживання. Усе — opt-in, в окремих процесах, з вивантаженням.

## K. Дизайн-система: Material 3 Expressive (обов’язкова для всього UI)

**Вимога до всіх 100 фіч і всіх milestone:** будь-який UI hodo — хром браузера, popup розширень, сторінки `hodo://`, діалоги, контроли форм — будується з єдиного набору токенів Material 3 Expressive (M3E). Фічі не малюють «своє»: кольори, форми, рух, шрифти й іконки беруться лише з токенів.

**Що це означає технічно.** M3E існує як специфікація та реалізації для Android (Compose) і Flutter; готового Rust-тулкіта під CPU-рендер без GPU немає. Тож для hodo це набір токенів + власні віджети на tiny-skia. Референс алгоритмів: Jetpack Compose material3 і бібліотека Android graphics-shapes (відкриті ліцензії; ліцензії перевірити) — читати як довідку, не тягнути як залежність.

**Рішення до старту (відкрите питання)**

- **A. `hodo-ui`** — власний невеликий retained-mode тулкіт на tiny-skia для хрому (таби, тулбар, меню, діалоги). Плюси: повний контроль над пружинами й morph, не залежить від зрілості CSS-рушія. Мінуси: `userChrome.css` (фіча 45) на хромі не працюватиме; дерево доступності будувати вручну.
- **B. Хром як внутрішні HTML/CSS-сторінки** на власному рушії. Плюси: dogfooding, userChrome.css, гаряче перезавантаження тем. Мінуси: потрібні flexbox/grid, border-radius, тіні, transitions, SVG, custom properties (M7/M8, фічі 6–7) — UI відсувається на місяці.
- **Рекомендація:** A для хрому зараз + спільний шар токенів; сторінки `hodo://` (налаштування, tasks, data, privacy report, нова вкладка) — HTML/CSS на рушії з тих самих токенів (це заодно тестує рушій). Міграцію хрому на B розглянути, коли рушій витягне.

### K.1 Токени — єдине джерело правди

- Один файл токенів (напр. `design/tokens.toml`) → кодоген у Rust-константи (для `hodo-ui`) і в CSS custom properties (`--md-sys-color-primary` тощо) для `hodo://`-сторінок.
- Жодних «магічних» кольорів/радіусів/таймінгів у коді: перевірка в CI, що UI-крейти не містять літералів кольору й тривалості поза кодогеном.
- Значення брати з офіційної специфікації (m3.material.io), а не з пам’яті; набір токенів версіонувати.

### K.2 Колір

- Dynamic color: схема з seed-кольору (HCT, тональні палітри); світла/темна тема й рівні контрасту standard / medium / high. Перевірити готові крейти (напр. порт Material Color Utilities) — брати лише якщо без `unsafe` і невеликі; інакше портувати.
- Ролі: primary / secondary / tertiary (+ container, on-*), error, surface і `surface-container` від lowest до highest, outline / outline-variant, inverse-*, scrim. Expressive віддає перевагу великим тональним поверхням (containment кольором), а не тіням.
- Джерела seed: вибір користувача, акцент ОС, колір workspace (фіча 36), `theme-color` поточної сторінки (тінт тулбара з обов’язковою перевіркою контрасту), опційно профіль.
- Контраст: автоперевірка WCAG для пар «on-\* / фон» у тестах; схема, що не проходить мінімум, автоматично піднімається на рівень контрасту.
- Веб-контент: `prefers-color-scheme`, `color-scheme`, `accent-color`, `forced-colors` (стик із фічею 84 і M8).

### K.3 Форма

- Шкала радіусів зі специфікації (від none до full, включно з розширеними large-increased / extra-large-increased / extra-extra-large) — лише через токени.
- Бібліотека з 35 фігур (cookie, flower, scallop, burst, clover, heart…) для аватарів профілів і workspaces (фіча 36), індикаторів, плейсхолдерів фавіконок.
- Shape morph у два етапи: (1) інтерполяція радіусів кутів (pill ↔ rounded-rect: press, hover, toggle); (2) повний morph між фігурами (rounded-polygon morph за ідеєю graphics-shapes: однакова кількість вершин + зіставлення ознак; власна реалізація на `tiny-skia::Path`).
- Маски фігур кешувати в LRU — не перераховувати Path щокадру.

### K.4 Рух (motion physics)

- Для просторових змін — пружини, а не duration/easing. Дві ролі: **spatial** (позиція, розмір, форма; може перестрибувати) і **effects** (колір, прозорість; без перельоту). Кожна в трьох швидкостях: fast / default / slow. Схеми standard і expressive; за замовчуванням expressive.
- Орієнтовні значення (stiffness / damping ratio) за відкритими портами специфікації; **звірити з m3.material.io перед кодогеном:** expressive spatial — fast 800 / 0.6, default 380 / 0.8, slow 200 / 0.8; standard spatial — 1400 / 0.9, 700 / 0.9, 300 / 0.9; effects — fast 3800, default 1600, slow 800, усі з damping 1.0.
- Реалізація: аналітичний розв’язок пружини (underdamped / critically damped) — детермінований, без накопичення похибки інтегрування; переривання анімації зберігає швидкість (retargeting).
- Reduced motion (ОС або налаштування hodo): пружини → короткі fade, morph → crossfade; режим економії (фіча 98) вимикає декоративну анімацію.
- Бюджет: анімація = repaint, тому за замовчуванням анімації вмикаються лише після damage-rect (M5.1). Активна анімація запитує redraw лише поки не settle (поріг швидкості/зсуву), далі `ControlFlow::Wait`; ліміт одночасних анімацій; без алокацій на кадр.

### K.5 Типографіка

- Шкала display / headline / title / body / label × large / medium / small + emphasized-варіанти (важчі накреслення).
- Шрифт — тільки з відкритою ліцензією (напр. Roboto Flex, OFL); перевірити покриття української: і, ї, є, ґ, апостроф. Пропрієтарні шрифти Google не використовувати.
- Обмеження: fontdue (поточний растеризатор) не підтримує осі variable fonts (перевірити в актуальній версії). Варіанти: (а) статичні інстанси потрібних ваг (напр. 400 / 500 / 700), згенеровані з варіативного шрифту; (б) растеризатор з підтримкою variations (кандидати перевірити: swash, skrifa). Рішення разом з M7.2.
- Масштаб шрифту (ОС/налаштування) до 200% без поломки розкладки.

### K.6 Іконки

- Material Symbols (перевірити умови ліцензії): підмножина \~150–250 іконок → build-time конвертація SVG у попередньо скомпільовані path-дані для tiny-skia. Без SVG-парсера в рантаймі й без іконного variable-шрифту.
- Вісь fill (outlined → filled при виборі): два набори path + crossfade/morph; вага й оптичний розмір — кілька статичних варіантів.
- Кеш растрованих іконок за (id, розмір, колір, DPI) у LRU.

### K.7 Стани, висота, розкладка

- State layers поверх container-кольору (орієнтир: hover 8%, focus 10%, pressed 10%, dragged 16% — звірити); focus ring за специфікацією; мінімальна цільова область 48 dp.
- Висота: тональні поверхні замість важких тіней; де потрібна тінь — blur через кешовану 9-slice текстуру, не живий blur щокадру (CPU/RAM).
- Адаптивні класи розміру вікна (compact / medium / expanded / large / extra-large, breakpoints зі специфікації) і канонічні розкладки (list-detail, supporting pane) для side panel, reader, менеджерів; DPI-масштаб (фіча 90).
- Density (звичайна / компактна) для тулбара й таб-стрипа — через токени, а не окремий код.

### K.8 Мапінг UI hodo → компоненти M3E

- Вертикальні таби й дерево (фічі 34–35) → navigation rail (expressive, згортається/розгортається).
- Адресний рядок і командна палітра (39–40) → search bar / search view зі списком підказок.
- Кнопки back/forward/reload → icon buttons (toggle із зміною форми), connected button group; «нова вкладка» → FAB / FAB menu (звичайна / приватна / контейнер, фіча 37).
- Дії сторінки (reader, скріншот, закладка; фічі 46, 48, 100) → floating toolbar.
- Завантаження сторінки → wavy linear progress у тулбарі; короткі очікування (до \~5 с) у діалогах → loading indicator (morphing shapes).
- Меню й контекстні меню → menu з групами; «Зберегти / Зберегти як…» → split button.
- Діалоги (паролі 21, дозволи 19), snackbar (завантаження завершено), rich tooltips.
- Side panel (sidePanel розширень 59, reader, DevTools) → side sheet / supporting pane.
- Завантаження, tasks, privacy report (52, 29, 25) → списки, cards, chips, determinate/wavy progress.
- Налаштування (`hodo://settings`) → list + switches, sliders, segmented buttons, text fields.
- Нова вкладка → carousel (speed dial / недавні) + search bar.
- Бейджі розширень (M2.2, `setBadgeText`) → badge; workspaces (36) → колірна роль + shape-аватар із 35 фігур.
- Форми у веб-контенті (M7.3) → UA-стилі контролів у вигляді M3: checkbox/radio/switch-подібні, outlined text field, select, тонкі скролбари, selection/caret/focus ring.

### K.9 Доступність власного UI

- Тулкіт малює пікселі, тож дерево доступності будуємо самі: з widget-дерева віддавати accessibility tree (кандидат: AccessKit — перевірити актуальність і інтеграцію з winit; стик із фічею 83).
- Клавіатурна навігація всіма віджетами (Tab / стрілки), видимий focus ring, ролі/назви/стани для кожного віджета, рівні контрасту, reduced motion, масштаб тексту.

### K.10 Продуктивність і RAM

- Хром малюється в окремому малому буфері, page-шар — окремо; композиція з damage (M5). Кеші (іконки, маски форм, glyph, тіні) мають спільний бюджет і LRU; пікселі хрому ≪ пікселів сторінки.
- Ціль: відкриття/закриття таба, hover, state layer, morph — у межах бюджету кадру; \~60 fps на типовому ноутбуці без GPU (калібрувати за `hodo-perf`). Додати сценарії в `hodo-perf`: анімація відкриття таба, hover по ряду кнопок, скрол списку в side panel.
- State layer — плоский alpha-overlay (дешево); дорогі blur-ефекти не робити.

### K.11 Тестування

- Golden-скріншоти (`hodo-tests`) для кожного компонента × стан (enabled/hover/focus/pressed/disabled/selected) × light/dark × standard/high contrast × масштаб 100%/200%.
- Токени: тест відповідності згенерованих значень еталону. Пружини: числові тести (без перельоту для effects, перельот для expressive spatial, retargeting, час settle).
- a11y-дерево; перевірка контрасту; fuzz на вхід теми (довільний seed, неіснуючі ролі) без паніки.
- Перф-регресії на анімаційних сценаріях.

### K.12 Ліцензії й бренд

Перед використанням перевірити ліцензію кожного ассета, шрифту й коду-референсу; пропрієтарні шрифти не використовувати; hodo не подавати як продукт Google.

### K.13 Порядок впровадження

1. **Фундамент:** токени + кодоген, dynamic color з контрастами, типографіка, шкала форм, state layers, іконки.
2. **Базові компоненти:** buttons / icon buttons, text field, search bar, меню, діалоги, tooltips, switch/checkbox/radio, navigation rail (таби), прогрес.
3. **Рух:** аналітичні пружини, press/hover/toggle morph радіусів, loading indicator, wavy progress. За замовчуванням — після M5.1.
4. **Експресивні компоненти:** button groups, split button, FAB menu, floating/docked toolbar, carousel, повна бібліотека 35 фігур і morph.
5. **Інтеграція з веб-контентом:** тінт за `theme-color`, UA-стилі форм і скролбарів, прив’язка до workspaces, налаштування персоналізації (seed, контраст, density, motion).

**DoD дизайн-системи:** усі поверхні з мапінгу K.8 використовують лише токени; golden-набір зелений; reduced motion і high contrast працюють; a11y-дерево для хрому є; perf-бюджет виконується; каталог усіх компонентів (скріншоти) генерується в CI.
